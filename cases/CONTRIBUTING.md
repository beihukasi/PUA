# 贡献指南

感谢你有兴趣为这个项目贡献案例！这份指南会帮助你了解整个流程。

## 核心理念

这个项目的目的是建立一个开放、真实的社交互动知识库。每个人的经历都是独特的，你的案例——无论结果是顺利还是不顺利——对其他人都可能有启发。

我们鼓励诚实和具体的分享，而不是追求"完美"的案例。

## 贡献之前

1. **阅读已有案例**：先看看 `example-cafe.md` 和其他案例，感受一下风格和深度。
2. **保护隐私**：不要使用真实姓名。用代称或模糊化处理（如"对方"、"她"、"小明"）。
3. **保持尊重**：所有提及的当事人都值得被尊重。避免物化、贬低或冒犯性的描述。

## 如何贡献

### 第一步：Fork 并克隆仓库

```bash
git clone https://github.com/YOUR_USERNAME/pua-advice.git
cd pua-advice
```

### 第二步：创建你的案例文件

```bash
cp cases/TEMPLATE.md cases/YYYY-MM-DD-short-title.md
```

用你的案例日期和一个简短的英文标题替换文件名。例如：

```bash
cp cases/TEMPLATE.md cases/2024-03-15-bookstore-meet.md
```

### 第三步：填写案例

用 Markdown 编辑器打开你的新文件，按照模板填写。几个要点：

- **诚实为上**：不需要美化结果。一个诚实的"不顺利"案例比一个虚构的"顺利"案例更有价值。
- **具体胜过抽象**：尽量还原真实对话，而非概括"我们聊了一会儿"。
- **复盘是灵魂**：案例分析的价值在于反思。"做得好的地方"和"可以改进的地方"同样重要。
- **可复用的经验**：想想如果你的朋友遇到类似情况，你会给他什么建议？把它写下来。

### 第四步：提交 Pull Request

```bash
git add cases/YYYY-MM-DD-short-title.md
git commit -m "添加案例: [你的标题]"
git push origin main
```

然后在 GitHub 上创建一个 Pull Request。

## 案例质量标准

一个好的案例应该让读者能够：

- **理解背景**：清楚知道当时的环境、参与者的情况。
- **跟随过程**：能够想象出互动的大致经过。
- **学到东西**：从你的复盘中获得可操作的经验。

### 不接受的案例

- 包含真实姓名或可识别个人信息的案例（请在提交前匿名化处理）
- 纯虚构或幻想内容（我们追求真实经历）
- 包含冒犯性、歧视性或不尊重他人的描述
- 过于简略、没有任何反思内容的案例

## 匿名贡献

如果你希望匿名贡献，可以：

1. 在 Front Matter 的 `contributor` 字段填写 `匿名`
2. 通过创建一个不包含个人信息的 GitHub 账号提交 PR
3. 或者将案例文件发送给维护者代为提交

## 沟通与讨论

- **Issue**：如果你有改进模板、报告问题或提出建议的想法，欢迎开 Issue。
- **Discussion**：对于案例的讨论、经验的交流，请使用 Discussion 板块。
- **保持友善**：每个人都有自己的成长节奏。请用建设性的态度参与讨论。

## 致谢

每一位贡献者都会在项目的贡献者列表中被感谢（如果你选择匿名，我们也会尊重你的选择）。

你的一个案例，可能会帮助一个正在迷茫中的人。

再次感谢你的贡献。
